Waterfall Arithmetic Unit Foundation
A foundation is needed to perfectly manage project development and prevent AI agents (currently laying the groundwork) from creating a mess of computational clichés.
- The Waterfall Arithmetic Unit was born as a circuit, whether FPGA or final. Its role is to maximize pipelines for rapid computation, even for dynamic programs.
- Its one-dimensional concept is essential to understanding its essence, but a 2D implementation (and 3D is also possible) is necessary to realize its potential.
- Each unit can contain certain "operators," which can also be dynamically selected by the developer. They may not be present in every unit as needed, and therefore the program flow routing system is essential to properly distribute the program flow without bottlenecks or wasted computational potential. Routing can be predetermined, auto-adapted within the circuit, or chosen directly by the circuit. Each of these options tends to create a more or less lightweight and responsive circuit, depending on the need.
- The operations examined here are simple mathematical expressions, but the implementation of a "pseudo-C" language is necessary to create a complete test case. Due to the nature of the WAU, however, the classic pointer view is not optimal, since in an architecture like the WAU, it is necessary to be able to reside (or stagnate) data within or near the cores that process it, using external memory such as RAM, etc. only when efficient and necessary.
- Given the dynamic nature of operations that can be added or removed in a WAU, a common abstraction language is needed to manage every possible program and operation, maintaining compatibility and avoiding improper expression limitations.
- Data type management is also essential to maximize efficiency. A unit could handle as many data types as possible for compression or optimization (such as float16 and float32), or not, forcing the use of separate operating units.
